Share deletion with dependent snapshots

Share deletion with dependent snapshots¶

한국어 의존 스냅샷이 있는 share 삭제

어려운 용어·숙어

  • cascade deletion: 연쇄 삭제 - 부모 리소스를 지울 때 딸린 자식 리소스까지 함께 지우는 방식

  • deferred deletion: 지연 삭제 - quota를 먼저 반환하고 backend 삭제는 비동기·주기적으로 마무리하는 Manila 기능 (is_deferred_deletion_enabled 설정)

  • admission: 승인 단계 - API가 요청을 받아들이기 전에 권한·상태·범위를 검사하고 상태를 바꾸는 단계

  • share instance / snapshot instance: share 인스턴스 / 스냅샷 인스턴스 - 사용자에게 보이는 share·스냅샷의 실제 backend 사본을 나타내는 DB 레코드

  • hidden child: 숨은 자식 - 기본 목록 조회에서 빠지는 deferred 상태의 스냅샷

  • wrapper: 래퍼 - 내부 함수를 감싸 호출하는 공개 DB API 함수

  • quota release: quota 반환 - 삭제된 리소스가 쓰던 할당량을 프로젝트에 돌려주는 처리

  • RPC pin: RPC 버전 고정 - 롤링 업그레이드 중 옛 서비스가 이해하는 버전으로 RPC를 제한하는 설정

  • microversion: 마이크로버전 - 하위 호환성을 유지하며 REST API 변경을 단계적으로 도입하는 OpenStack 버전 체계

  • conditional update: 조건부 업데이트 - 현재 값이 기대한 값일 때만 원자적으로 바꾸는 DB 업데이트

  • row lock: 행 잠금 - 동시 변경을 막기 위해 DB 행을 잠시 잠그는 것

  • durable intent: 영속적 의도 기록 - 서비스가 재시작돼도 작업을 이어갈 수 있도록 남기는 기록

  • idempotent: 멱등 - 같은 작업을 여러 번 해도 결과가 한 번 한 것과 같은 성질

  • force delete: 강제 삭제 - 상태 검사를 건너뛰는 관리자 삭제. Manila에서는 backend 삭제가 실패해도 DB 레코드를 지움

  • reset-state: 상태 재설정 - 관리자가 리소스의 상태 값을 직접 바꾸는 작업

  • orphan: 고아 리소스 - DB에는 없고 backend에만 남은 리소스

  • driver CI: 드라이버 CI - 각 backend driver를 실제 스토리지로 검증하는 테스트 시스템

  • crash window: 크래시 구간 - 서비스가 그 사이에 죽으면 상태가 어긋날 수 있는 구간

  • exactly-once delivery: 정확히 한 번 전달 - 메시지가 중복이나 유실 없이 한 번만 처리된다는 보장

Allow users to delete a share and its ordinary snapshots with one request. Following Cinder, delete snapshots sequentially before deleting the share.

한국어 사용자가 share와 그 일반 스냅샷을 한 번의 요청으로 삭제할 수 있게 합니다. Cinder처럼, share를 삭제하기 전에 스냅샷을 순차적으로 삭제합니다.

Problem description¶

한국어 문제 설명

Ordinary share deletion checks for dependent snapshots. Users normally delete each snapshot, wait for completion, and then delete the share.

한국어 일반 share 삭제는 의존 스냅샷이 있는지 검사합니다. 사용자는 보통 스냅샷을 하나씩 삭제하고, 완료를 기다린 뒤 share를 삭제합니다.

Interaction with deferred deletion¶

한국어 지연 삭제(deferred deletion)와의 상호작용

Deferred deletion separates quota release from backend completion. The API marks instances deferred_deleting and sends an asynchronous manager RPC. The manager attempts quota release before its first driver deletion call. Backend failures leave error_deferred_deleting for periodic retry. A snapshot can therefore remain on the backend after quota has been returned; its status alone proves neither backend removal nor completed quota accounting.

한국어 지연 삭제는 quota 반환과 backend 삭제 완료를 분리합니다. API는 instance를 deferred_deleting으로 표시하고 비동기 manager RPC를 보냅니다. manager는 첫 driver 삭제 호출 전에 quota 반환을 시도합니다. backend 삭제가 실패하면 error_deferred_deleting 상태로 남고 주기 작업이 재시도합니다. 따라서 quota가 반환된 뒤에도 스냅샷이 backend에 남아 있을 수 있으며, 상태만으로는 backend에서 제거됐는지도, quota 처리가 끝났는지도 증명할 수 없습니다.

Ordinary DB snapshot lists exclude both deferred states unless list_deferred_delete=True. The current share_snapshot_get_all_for_share wrapper discards its filters argument, and the existing parent dependency check uses that wrapper. An available share can consequently pass that check while hidden snapshots remain. A deferred parent is already rejected by the existing allowed-state check; the gap is an available parent with deferred children, including children left after the setting was disabled.

한국어 일반 DB 스냅샷 목록은 list_deferred_delete=True가 없으면 두 deferred 상태를 제외합니다. 현재 share_snapshot_get_all_for_share wrapper는 filters 인자를 버리고, 기존 부모 의존성 검사는 이 wrapper를 사용합니다. 그 결과 숨겨진 스냅샷이 남아 있어도 available share가 검사를 통과할 수 있습니다. deferred 상태인 부모는 기존 허용 상태 검사에서 이미 거부되므로, 문제는 deferred 자식을 가진 available 부모입니다. 설정을 끈 뒤에 남은 자식도 여기에 포함됩니다.

Use Cases¶

한국어 사용 사례

  • Remove an obsolete share and its snapshots with one explicit request.

    한국어 더 이상 쓰지 않는 share와 그 스냅샷을 명시적인 요청 한 번으로 제거합니다.

  • Simplify cleanup of temporary environments and automation.

    한국어 임시 환경과 자동화의 정리 작업을 단순화합니다.

Proposed change¶

한국어 제안하는 변경

Add cascade=true to share DELETE. Omitted or false preserves existing behavior. Cascade deletes children through their existing manager lifecycle.

한국어 share DELETE에 cascade=true를 추가합니다. 생략하거나 false면 기존 동작을 유지합니다. cascade는 자식들을 기존 manager 생명주기를 통해 삭제합니다.

Scope¶

한국어 범위

Support one non-replicated share instance and one instance per ordinary snapshot. Existing checks continue to reject replicated shares (has_replicas) and busy shares (task_state in BUSY_TASK_STATES, which covers migration). Backups and group snapshot members remain blockers; existing share-group checks remain. Shares created from snapshots are not recursively deleted.

한국어 복제되지 않은 share instance 하나와, 일반 스냅샷마다 instance가 하나인 경우를 지원합니다. 복제된 share(has_replicas)와 busy share(task_state가 BUSY_TASK_STATES에 속함, migration 포함)는 기존 검사가 계속 거부합니다. backup과 group snapshot member는 계속 삭제를 막고, 기존 share group 검사도 유지됩니다. 스냅샷에서 생성된 share는 재귀적으로 삭제하지 않습니다.

Admission¶

한국어 승인(admission) 단계

Cascade requires is_deferred_deletion_enabled=False in manila-api ([DEFAULT]). Return 409 Conflict when enabled, even with no children, or when any child instance is deferred_deleting or error_deferred_deleting. Deferred work is neither joined nor converted into immediate cascade deletion. Rejecting regardless of child count keeps the result of a cascade request a function of deployment configuration rather than of the share’s current snapshot count.

한국어 cascade를 쓰려면 manila-api의 [DEFAULT]에 is_deferred_deletion_enabled=False가 필요합니다. 이 설정이 켜져 있으면 자식이 없어도 409 Conflict를 반환하고, 자식 instance 중 하나라도 deferred_deleting이나 error_deferred_deleting이면 역시 409를 반환합니다. 진행 중인 deferred 작업에 합류하지도, 즉시 cascade 삭제로 전환하지도 않습니다. 자식 수와 관계없이 거부해야 cascade 요청의 결과가 share의 현재 스냅샷 수가 아니라 배포 설정에 따라 결정됩니다.

Before admission:

한국어 승인 전에:

  • Check share:delete and every child’s share:delete_snapshot as the requesting user; preserve deletion locks and busy checks.

    한국어 요청한 사용자 권한으로 share:delete와 모든 자식의 share:delete_snapshot을 검사합니다. 삭제 잠금(lock)과 busy 검사를 유지합니다.

  • Load every child instance with an instance-level, parent-scoped lookup (share_snapshot_instance_get_all_with_filters by share_instance_ids), which never excludes deferred states. Do not rely on share_snapshot_get_all_for_share. Reject either deferred state with 409 before state, quota, or RPC changes.

    한국어 모든 자식 instance를 부모 범위의 instance 단위 조회(share_instance_ids로 share_snapshot_instance_get_all_with_filters 호출)로 가져옵니다. 이 조회는 deferred 상태를 제외하지 않습니다. share_snapshot_get_all_for_share에는 의존하지 않습니다. 두 deferred 상태 중 하나라도 있으면 상태·quota·RPC를 바꾸기 전에 409로 거부합니다.

  • Allow parent available, error, or inactive and child available or error. Preserve existing parent rejection for both deferred states. Require a usable host with children and reject active clone creation.

    한국어 부모는 available, error, inactive를, 자식은 available, error를 허용합니다. 두 deferred 상태에 대한 기존 부모 거부를 유지합니다. 자식이 있으면 사용 가능한 host가 있어야 하고, 진행 중인 clone 생성은 거부합니다.

  • Conditional DB-update helpers atomically change the parent and selected children to deleting in one transaction. Reject changed states or child membership without updating any target.

    한국어 조건부 DB 업데이트 helper가 한 트랜잭션 안에서 부모와 선택된 자식을 원자적으로 deleting으로 바꿉니다. 그사이 상태나 자식 구성이 바뀌었으면 어떤 대상도 업데이트하지 않고 거부합니다.

Reuse available-state checks for snapshot creation, clone creation, and revert. Snapshot manage and any forced snapshot creation must reject a deleting share. Recheck states at DB writes for create/manage, clone, revert, and snapshot deletion with short row locks, released before backend calls, to prevent races.

한국어 스냅샷 생성, clone 생성, revert에는 기존 available 상태 검사를 재사용합니다. 스냅샷 manage와 강제(forced) 스냅샷 생성은 deleting 상태인 share를 거부해야 합니다. 경쟁 상태를 막기 위해 create/manage, clone, revert, 스냅샷 삭제의 DB 쓰기 시점에 짧은 row lock으로 상태를 다시 확인하고, backend 호출 전에 lock을 해제합니다.

Manager flow¶

한국어 Manager 처리 흐름

After admission, send one versioned manager RPC. Keep the parent deleting during child work; with zero children, use existing non-deferred share deletion. If the share RPC API is pinned below the version that adds cascade, the API returns 409 before any state change, so mixed-version deployments never send cascade work to an older manager.

한국어 승인 후 versioned manager RPC를 한 번 보냅니다. 자식을 처리하는 동안 부모는 deleting을 유지합니다. 자식이 없으면 기존 비지연(non-deferred) share 삭제를 사용합니다. share RPC API가 cascade를 추가한 버전보다 낮게 고정(pin)돼 있으면 API는 상태를 바꾸기 전에 409를 반환합니다. 그래서 버전이 섞인 배포에서도 cascade 작업이 옛 manager로 가지 않습니다.

  1. Delete selected snapshots in a stable, sequential for loop, reusing access cleanup, driver deletion, DB cleanup, and quota release with force=False and deferred_delete=False.

    한국어 선택된 스냅샷을 정해진 순서의 순차 for 루프로 삭제합니다. access 정리, driver 삭제, DB 정리, quota 반환을 force=False, deferred_delete=False로 재사용합니다.

  2. Stop on the first exception or retained child; set parent error_deleting.

    한국어 첫 예외가 나거나 자식이 남으면 멈추고 부모를 error_deleting으로 설정합니다.

  3. Re-query every remaining instance, including deferred states. Only an empty result permits existing parent deletion with force=False and deferred_delete=False. A filtered-empty ordinary list is insufficient.

    한국어 deferred 상태를 포함해 남은 instance를 모두 다시 조회합니다. 결과가 비어 있을 때만 force=False, deferred_delete=False로 기존 부모 삭제를 진행합니다. 필터 때문에 비어 보이는 일반 목록으로는 충분하지 않습니다.

Failure and recovery¶

한국어 실패와 복구

If child 4 of 10 has a backend deletion failure, children 1-3 are gone; child 4 is error_deleting; children 5-10 stay deleting without driver calls. The parent becomes error_deleting without a driver call. Ordinary retry preserves status checks; it cannot restart failed or active work.

한국어 10개 중 4번째 자식의 backend 삭제가 실패하면, 1~3번은 이미 삭제됐고 4번은 error_deleting, 5~10번은 driver 호출 없이 deleting으로 남습니다. 부모는 driver 호출 없이 error_deleting이 됩니다. 일반 재시도는 상태 검사를 그대로 적용하므로, 실패했거나 진행 중인 작업을 다시 시작할 수 없습니다.

Interrupted resources may remain deleting as in ordinary deletion, with no durable intent or automatic resumption.

한국어 중단된 리소스는 일반 삭제와 마찬가지로 deleting에 남을 수 있으며, 영속적인 의도 기록(durable intent)이나 자동 재개는 없습니다.

Administrator retry¶

한국어 관리자 재시도

Cinder recovers this state with DELETE ?cascade=true&force=true, which skips status checks and re-runs the loop with real driver calls. Manila’s force instead discards DB rows when backend deletion fails, so reusing it would hide backend failures rather than retry them. This proposal adds a retry that keeps Cinder’s recovery path without Manila’s force semantics.

한국어 Cinder는 이 상태를 DELETE ?cascade=true&force=true로 복구합니다. 이 요청은 상태 검사를 건너뛰고 실제 driver 호출로 루프를 다시 실행합니다. 반면 Manila의 force는 backend 삭제가 실패하면 DB row를 버리므로, 이를 재사용하면 backend 실패를 재시도하는 대신 숨기게 됩니다. 이 제안은 Manila force의 의미를 빼고 Cinder의 복구 경로를 유지하는 재시도를 추가합니다.

A cascade request on a parent in deleting or error_deleting is a retry. It requires the new share:delete_cascade_retry policy, which defaults to the same admin rule as share:force_delete; without it, the existing invalid-status rejection applies. A retry:

한국어 deleting이나 error_deleting 상태인 부모에 대한 cascade 요청은 재시도로 봅니다. 새 share:delete_cascade_retry policy가 필요하며, 기본값은 share:force_delete와 같은 관리자 규칙입니다. 이 policy가 없으면 기존의 잘못된 상태(invalid-status) 거부가 적용됩니다. 재시도는 다음과 같이 동작합니다:

  • Admits the parent in deleting or error_deleting and children in available, error, deleting, or error_deleting.

    한국어 부모는 deleting이나 error_deleting, 자식은 available, error, deleting, error_deleting 상태를 허용합니다.

  • Applies every other admission rule unchanged: deferred deletion disabled, no deferred child states, no replicas, busy task states, backups, or group snapshot members, and locks honored.

    한국어 나머지 승인 규칙은 그대로 적용합니다: 지연 삭제 비활성, deferred 자식 상태 없음, replica·busy task 상태·backup·group snapshot member 없음, 잠금 존중.

  • Atomically moves the parent and remaining children to deleting and sends the same manager RPC. Children already deleted are no longer listed, so the loop resumes where it stopped.

    한국어 부모와 남은 자식을 원자적으로 deleting으로 바꾸고 같은 manager RPC를 보냅니다. 이미 삭제된 자식은 더 이상 목록에 없으므로 루프는 멈춘 곳부터 이어집니다.

  • Uses force=False throughout. A repeated backend failure stops the loop again with error_deleting; no DB row is discarded.

    한국어 처음부터 끝까지 force=False를 사용합니다. backend 실패가 반복되면 루프는 다시 error_deleting으로 멈추고, DB row는 버리지 않습니다.

The API cannot distinguish a stopped worker from one still running. The administrator must confirm that the earlier worker is no longer processing the share, for example after error_deleting or a manila-share restart, before retrying. This matches the precondition of Cinder’s force cascade.

한국어 API는 멈춘 worker와 아직 실행 중인 worker를 구분할 수 없습니다. 관리자는 재시도 전에 이전 worker가 더 이상 이 share를 처리하지 않는지 확인해야 합니다(예: error_deleting이 된 뒤, 또는 manila-share 재시작 후). 이는 Cinder force cascade의 전제 조건과 같습니다.

Existing individual force-delete and reset-state recovery remain available.

한국어 기존의 개별 force-delete와 reset-state 복구도 계속 사용할 수 있습니다.

Out of scope¶

한국어 범위 밖

Parent deletion must wait for actual child backend deletion. Deferred support needs durable parent intent, coordination with periodic retries, and quota accounting that prevents a second release. These require a separate follow-up specification; this proposal adds none of that machinery.

한국어 부모 삭제는 자식의 실제 backend 삭제를 기다려야 합니다. 지연 삭제를 지원하려면 영속적인 부모 의도 기록, 주기 재시도와의 조율, quota 이중 반환을 막는 회계 처리가 필요합니다. 이는 별도의 후속 스펙이 다뤄야 하며, 이 제안은 그런 장치를 추가하지 않습니다.

This specification covers non-deferred deletion with hidden-child rejection. A separate deferred-support spec must resolve durable intent, periodic retries, and idempotent quota accounting. Automatic restart recovery, schema changes, and force-cascade remain follow-up work; immediate deletion retains its existing DB/quota crash window.

한국어 이 스펙은 숨은 자식을 거부하는 비지연 삭제를 다룹니다. 영속적 의도 기록, 주기 재시도, 멱등적 quota 회계는 별도의 지연 삭제 지원 스펙이 해결해야 합니다. 자동 재시작 복구, 스키마 변경, force-cascade는 후속 작업으로 남으며, 즉시 삭제는 기존의 DB/quota 크래시 구간을 그대로 가집니다.

Alternatives¶

한국어 대안

  • Keep client orchestration: repeats authorization, ordering, and recovery logic in every client instead of one server-side lifecycle.

    한국어 클라이언트 오케스트레이션 유지: 서버 측 생명주기 하나 대신 모든 클라이언트가 권한 검사, 순서, 복구 로직을 반복해야 합니다.

  • Delete the parent then clean child DB rows: cannot prove backend snapshot deletion and bypasses access cleanup and ordinary quota handling.

    한국어 부모를 먼저 삭제하고 자식 DB row를 정리: backend 스냅샷 삭제를 증명할 수 없고, access 정리와 일반 quota 처리를 우회합니다.

  • Require a bulk-delete driver method: forces changes across drivers before availability; existing per-resource methods suffice for this proposal.

    한국어 일괄 삭제 driver 메서드 요구: 기능을 쓰기 전에 여러 driver를 바꿔야 합니다. 이 제안에는 기존 리소스별 메서드로 충분합니다.

  • Reuse force for cascade recovery, as Cinder does: rejected because Manila’s force discards DB rows after backend failures, which can orphan backend snapshots instead of retrying them.

    한국어 Cinder처럼 cascade 복구에 force 재사용: 기각. Manila의 force는 backend 실패 후 DB row를 버려서, backend 스냅샷을 재시도하는 대신 고아로 남길 수 있습니다.

  • Restore untouched children after a failure: pass each child’s prior status in the RPC and return children that received no driver call to that status. Not selected; administrator retry covers this case and also recovers resources left deleting by a manila-share restart.

    한국어 실패 후 손대지 않은 자식 복원: 각 자식의 이전 상태를 RPC로 넘기고, driver 호출을 받지 않은 자식을 그 상태로 되돌립니다. 미채택. 관리자 재시도가 이 경우를 다루고, manila-share 재시작으로 deleting에 남은 리소스까지 복구합니다.

  • Restrict deployment to deferred-disabled environments: selected here, with explicit hidden-child rejection. Waiting for periodic deletion or overriding deferred policy with a force-cascade action requires a separate design.

    한국어 지연 삭제가 꺼진 환경으로 제한: 이번에 선택한 방식이며, 숨은 자식을 명시적으로 거부합니다. 주기 삭제를 기다리거나 force-cascade 동작으로 지연 삭제 정책을 덮어쓰는 것은 별도 설계가 필요합니다.

Data model impact¶

한국어 데이터 모델 영향

None. Cascade intent is passed only through the manager RPC; no new fields, status values, or migrations are added.

한국어 없음. cascade 의도는 manager RPC로만 전달되며, 새 필드·상태 값·마이그레이션을 추가하지 않습니다.

REST API impact¶

한국어 REST API 영향

In the new microversion, represented by 2.N:

DELETE /v2/{project_id}/shares/{share_id}?cascade=true
X-OpenStack-Manila-API-Version: 2.N

한국어 2.N으로 표기하는 새 microversion에서:

한국어 (요청 예시) 2.N microversion 헤더와 cascade=true 쿼리 파라미터로 share DELETE를 요청합니다.

Return 202 with an empty body; backend completion is asynchronous. Invalid or duplicate booleans and explicit cascade below 2.N return 400. Keep policy/missing-resource 403/404 and existing invalid-status mappings. Unsupported scope, overlapping admission, enabled deferred deletion, either deferred child state, or an RPC version pin below cascade support return 409. A retry on a deleting or error_deleting parent without share:delete_cascade_retry keeps the existing invalid-status response. No new query parameter is added for retry, and the force-delete body is unchanged.

한국어 202와 빈 본문을 반환하며, backend 삭제 완료는 비동기입니다. 잘못되거나 중복된 boolean 값, 2.N 미만에서 명시한 cascade는 400을 반환합니다. policy 거부·리소스 없음의 403/404와 기존 잘못된 상태 매핑은 유지합니다. 지원하지 않는 범위, 겹치는 승인, 지연 삭제 활성화, 두 deferred 자식 상태 중 하나, cascade 지원 버전 미만의 RPC pin은 409를 반환합니다. share:delete_cascade_retry 없이 deleting이나 error_deleting 부모에 재시도하면 기존의 잘못된 상태 응답을 그대로 받습니다. 재시도용 쿼리 파라미터는 추가하지 않으며, force-delete 본문도 바뀌지 않습니다.

Driver impact¶

한국어 드라이버 영향

None. No new driver method or capability is added; delete_snapshot and delete_share are reused. Driver CI must verify snapshot deletion while the parent is deleting. Backend dependency failures retain the parent. Administrator retry may call delete_snapshot or delete_share for a resource already removed from the backend; drivers that report such a call as an error stop the retry safely, and driver CI should cover this case.

한국어 없음. 새 driver 메서드나 capability를 추가하지 않고 delete_snapshot과 delete_share를 재사용합니다. driver CI는 부모가 deleting인 동안 스냅샷 삭제가 되는지 검증해야 합니다. backend 의존성 때문에 실패하면 부모는 유지됩니다. 관리자 재시도는 이미 backend에서 제거된 리소스에 delete_snapshot이나 delete_share를 호출할 수 있습니다. 이런 호출을 오류로 보고하는 driver는 재시도를 안전하게 멈추며, driver CI가 이 경우를 다뤄야 합니다.

Security impact¶

한국어 보안 영향

Grant no force permissions; honor locks and authorize each target before manager elevation, because one request deletes multiple resources. Retry adds the admin-default share:delete_cascade_retry policy; it relaxes only status checks and never discards DB rows.

한국어 force 권한을 부여하지 않습니다. 한 요청이 여러 리소스를 삭제하므로, manager 권한 상승 전에 잠금을 존중하고 대상마다 권한을 검사합니다. 재시도는 관리자 기본값의 share:delete_cascade_retry policy를 추가하며, 이 policy는 상태 검사만 완화하고 DB row를 버리지 않습니다.

Notifications impact¶

한국어 알림 영향

None. Existing share.delete.start/share.delete.end events and payloads stay in the parent lifecycle; child-phase failures never enter it.

한국어 없음. 기존 share.delete.start/share.delete.end 이벤트와 payload는 부모 생명주기에만 머물며, 자식 단계의 실패는 여기에 들어가지 않습니다.

Other end user impact¶

한국어 기타 최종 사용자 영향

Add --cascade with microversion negotiation. Document partial failure, deferred-mode rejection, administrator retry, and existing administrative recovery.

한국어 microversion 협상과 함께 –cascade를 추가합니다. 부분 실패, 지연 삭제 모드에서의 거부, 관리자 재시도, 기존 관리자 복구 방법을 문서화합니다.

Performance Impact¶

한국어 성능 영향

Sequential deletion keeps one manager worker busy for the child phase. Backend call counts follow ordinary deletion; admission adds DB checks and short locks.

한국어 순차 삭제는 자식 단계 동안 manager worker 하나를 점유합니다. backend 호출 수는 일반 삭제와 같고, 승인 단계에 DB 검사와 짧은 lock이 추가됩니다.

Other deployer impact¶

한국어 기타 배포자 영향

Set is_deferred_deletion_enabled=False in manila-api’s [DEFAULT] to use cascade. Cascade becomes available once every manila-share service is upgraded and the RPC pin is lifted. Disabling it does not make pending deferred children eligible: both deferred states must be absent. No new option is added; non-cascade behavior and existing immediate quota handling remain unchanged. Operators who delegate retry must grant share:delete_cascade_retry explicitly.

한국어 cascade를 쓰려면 manila-api의 [DEFAULT]에 is_deferred_deletion_enabled=False를 설정합니다. 모든 manila-share 서비스가 업그레이드되고 RPC pin이 해제되면 cascade를 쓸 수 있습니다. 설정을 꺼도 대기 중인 deferred 자식이 대상이 되지는 않으며, 두 deferred 상태가 모두 없어야 합니다. 새 옵션은 추가하지 않고, cascade가 아닌 동작과 기존 즉시 quota 처리는 바뀌지 않습니다. 재시도를 다른 사람에게 위임하려는 운영자는 share:delete_cascade_retry를 명시적으로 부여해야 합니다.

Developer impact¶

한국어 개발자 영향

Shared DB state-update helpers and snapshot-operation guards must cooperate with cascade admission; update their callers and tests with the manager RPC.

한국어 공용 DB 상태 업데이트 helper와 스냅샷 작업 guard가 cascade 승인과 맞물려 동작해야 합니다. 호출부와 테스트를 manager RPC와 함께 갱신합니다.

한국어 주 담당자: Inyong Hong (hong-p).

한국어 작업 항목

  • Register the blueprint and assign the microversion.

    한국어 blueprint를 등록하고 microversion을 배정합니다.

  • Add hidden-child admission, atomic updates, and the identified state checks.

    한국어 숨은 자식 승인 검사, 원자적 업데이트, 앞서 정한 상태 검사를 추가합니다.

  • Add sequential manager deletion, RPC, and the unfiltered completion gate.

    한국어 순차 manager 삭제, RPC, 필터 없는 완료 게이트를 추가합니다.

  • Add the share:delete_cascade_retry policy and retry admission.

    한국어 share:delete_cascade_retry policy와 재시도 승인을 추가합니다.

  • Add client support, tests, API history, documentation, and a release note.

    한국어 클라이언트 지원, 테스트, API 이력, 문서, release note를 추가합니다.

Dependencies¶

한국어 의존성

None. Existing libraries suffice; client support is covered under Work Items.

한국어 없음. 기존 라이브러리로 충분하며, 클라이언트 지원은 작업 항목에 포함돼 있습니다.

Testing¶

한국어 테스트

  • Omitted/false cascade, zero children, policy denial, and invalid versions.

    한국어 cascade 생략/false, 자식 없음, policy 거부, 잘못된 버전.

  • Enabled deferred deletion returns 409, even without children.

    한국어 지연 삭제가 켜져 있으면 자식이 없어도 409를 반환합니다.

  • With the setting disabled and parent available, either deferred child state, alone or mixed with ordinary children, returns 409 without state, quota, RPC, or notification changes. Test the filter-discarding wrapper gap.

    한국어 설정이 꺼져 있고 부모가 available일 때, 두 deferred 자식 상태 중 하나가 단독으로 있든 일반 자식과 섞여 있든 상태·quota·RPC·알림 변경 없이 409를 반환합니다. filters를 버리는 wrapper로 생기는 공백도 테스트합니다.

  • A deferred parent retains existing rejection; turning the setting off does not bypass hidden-child checks. The completion gate also includes them.

    한국어 deferred 부모는 기존 거부를 유지하고, 설정을 꺼도 숨은 자식 검사를 우회하지 않습니다. 완료 게이트도 숨은 자식을 포함합니다.

  • Instance/status validation, conflicting-update rollback, and create/manage (including forced creation), clone, revert, and concurrent deletion races.

    한국어 instance/상태 검증, 충돌하는 업데이트의 롤백, create/manage(강제 생성 포함), clone, revert, 동시 삭제 경쟁 상태.

  • Child-before-parent ordering, child-4 failure, quota/access cleanup, unchanged notifications, and admin recovery.

    한국어 자식 먼저·부모 나중 순서, 4번 자식 실패, quota/access 정리, 알림 불변, 관리자 복구.

  • Retry after child-4 failure resumes from child 4 and deletes the parent; retry without the policy is rejected; a repeated failure stops again without discarding DB rows; retry still rejects deferred states.

    한국어 4번 자식 실패 후 재시도하면 4번부터 이어서 부모까지 삭제합니다. policy 없는 재시도는 거부됩니다. 실패가 반복되면 DB row를 버리지 않고 다시 멈춥니다. 재시도도 deferred 상태는 계속 거부합니다.

Add DB concurrency and Tempest share-with-snapshots tests; validate driver CI. No exactly-once delivery or automatic restart recovery is claimed.

한국어 DB 동시성 테스트와 스냅샷이 있는 share에 대한 Tempest 테스트를 추가하고 driver CI로 검증합니다. 정확히 한 번 전달(exactly-once)이나 자동 재시작 복구는 보장하지 않습니다.

Documentation Impact¶

한국어 문서 영향

Document the option, supported scope, deferred configuration/rejection reasons, asynchronous completion, administrator retry and its precondition, and force-delete/reset-state recovery.

한국어 옵션, 지원 범위, 지연 삭제 설정과 거부 사유, 비동기 완료, 관리자 재시도와 그 전제 조건, force-delete/reset-state 복구를 문서화합니다.
