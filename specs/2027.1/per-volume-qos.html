Per-volume QoS at create time and online update

Per-volume QoS at create time and online update¶

한국어 볼륨 생성 시점과 온라인 변경을 지원하는 볼륨별 QoS

어려운 용어·숙어

  • QoS spec: QoS 사양 - 볼륨 타입에 연결해 IOPS·대역폭 상한 같은 성능 제한을 정의하는 key/value 묶음

  • consumer (back-end / front-end): 적용 주체 - QoS를 스토리지가 적용하는지(back-end), 하이퍼바이저가 적용하는지(front-end)

  • retype: 타입 변경 - 볼륨의 볼륨 타입을 바꾸는 작업으로, 백엔드에 따라 마이그레이션이 동반될 수 있음

  • sustained upper limit / burst limit: 지속 상한 / 버스트 허용치 - 계속 유지되는 최대치와, 짧은 순간 초과를 허용하는 최대치

  • microversion: 마이크로버전 - 하위 호환성을 유지하며 REST API 변경을 단계적으로 도입하는 OpenStack 버전 체계

  • capability: 백엔드 기능 정보 - 드라이버가 volume stats로 보고하고 스케줄러가 백엔드 선택에 사용하는 값

  • NoValidBackend: 적합한 백엔드 없음 - 스케줄러가 요청 조건을 만족하는 백엔드를 찾지 못했을 때의 오류

  • user message: 사용자 메시지 - 비동기 작업 실패를 사용자에게 알리기 위해 Cinder가 남기는 메시지

  • RPC cast: 비동기 RPC 호출 - 응답을 기다리지 않고 보내는 RPC 호출

  • rolling upgrade: 롤링 업그레이드 - 서비스를 멈추지 않고 노드를 차례로 업그레이드하는 방식

  • obj_make_compatible: 객체 하위 호환 변환 - 이전 버전 서비스에 보낼 때 새 필드를 제거하는 versioned object 메서드

  • extra spec: 추가 사양 - 볼륨 타입에 붙이는 key/value 속성으로, 스케줄링이나 드라이버 동작을 지정함

  • scoped key: 범위 접두어가 붙은 키 - per_volume_qos:처럼 콜론 앞 접두어가 있는 키로, capabilities:가 아니면 스케줄러가 무시함

  • project member: 프로젝트 멤버 - 관리자 권한 없이 프로젝트 자원을 사용하는 일반 사용자 역할

  • CapabilitiesFilter: 기능 필터 - 볼륨 타입 extra spec과 백엔드가 보고한 capability를 비교해 백엔드를 고르는 스케줄러 필터

  • effective limit: 실제 적용 상한 - 볼륨별 값, 타입 기본값, 범위 최대값 순으로 계산해 실제로 적용하는 값

The URL of launchpad blueprint:

한국어 런치패드 블루프린트 URL:

https://blueprints.launchpad.net/cinder/+spec/per-volume-qos

Allow maximum IOPS and throughput limits to be set on an individual volume, at creation and later on an existing volume, without a dedicated volume type. Project members can set them within a range allowed by the volume type, and administrators can set any value.

한국어 전용 볼륨 타입 없이 개별 볼륨에 최대 IOPS와 처리량 상한을 설정할 수 있게 합니다. 볼륨 생성 시점은 물론 이미 있는 볼륨에도 나중에 설정할 수 있습니다. 프로젝트 멤버는 볼륨 타입이 허용하는 범위 안에서 설정할 수 있고, 관리자는 어떤 값이든 설정할 수 있습니다.

Problem description¶

한국어 문제 설명

QoS is bound to a volume type through a QoS spec. Giving volumes different limits requires one volume type per combination, which leads to many nearly identical types. Changing the limits of an existing volume requires a retype, which is heavy and may trigger a migration on some backends. Some deployments work around this with QoS values in volume metadata, but metadata is editable by the volume owner, so a tenant can raise its own limit.

한국어 QoS는 QoS spec을 통해 볼륨 타입에 묶여 있습니다. 볼륨마다 다른 상한을 주려면 조합마다 볼륨 타입이 하나씩 필요해, 거의 같은 타입이 많이 생깁니다. 기존 볼륨의 상한을 바꾸려면 retype이 필요한데, retype은 무거운 작업이고 일부 백엔드에서는 마이그레이션을 일으킬 수 있습니다. 일부 배포 환경은 볼륨 메타데이터에 QoS 값을 넣는 방식으로 우회하지만, 메타데이터는 볼륨 소유자가 수정할 수 있어 테넌트가 자기 상한을 직접 올릴 수 있습니다.

Use Cases¶

한국어 사용 사례

  • An operator creates a volume with max_iops=3000 and max_bps=125000000 without a type for those exact values.

    한국어 운영자가 정확히 그 값에 맞는 타입 없이 max_iops=3000, max_bps=125000000으로 볼륨을 생성합니다.

  • An operator changes the limits of an in-use volume without detaching or retyping it, or removes the override to return to the type default.

    한국어 운영자가 사용 중(in-use)인 볼륨을 분리(detach)하거나 retype하지 않고 상한을 변경하거나, 볼륨별 설정을 제거해 타입 기본값으로 되돌립니다.

  • An operator lets project members tune the limits of their own volumes, but only within bounds the operator chooses, for example 3000 to 16000 IOPS.

    한국어 운영자가 프로젝트 멤버에게 자기 볼륨의 상한 조정을 허용하되, 운영자가 정한 범위(예: 3000~16000 IOPS) 안에서만 허용합니다.

  • An end user raises the limits of its own volume within the range allowed by the volume type, but cannot go beyond that range.

    한국어 최종 사용자가 볼륨 타입이 허용하는 범위 안에서 자기 볼륨의 상한을 올리지만, 그 범위를 넘을 수는 없습니다.

Proposed change¶

한국어 제안하는 변경

Add two optional per-volume limits, max_iops and max_bps (bytes per second), stored in new columns of the volumes table, not in volume metadata. Both are sustained upper limits for read and write combined. Burst settings are out of scope: burst limits in the volume type QoS spec still apply unchanged.

한국어 선택 항목인 볼륨별 상한 두 개, max_iops와 max_bps(초당 바이트)를 추가하고, 볼륨 메타데이터가 아니라 volumes 테이블의 새 컬럼에 저장합니다. 둘 다 read와 write를 합친 지속 상한입니다. burst 설정은 범위 밖이며, 볼륨 타입 QoS spec의 burst 상한은 바뀌지 않고 그대로 적용됩니다.

This spec covers back-end QoS only (consumer=back-end): the limits are applied by the volume driver on the storage system. Front-end QoS specs are not changed and are still applied by the hypervisor, so the effective limit is the lower of the two.

한국어 이 스펙은 back-end QoS(consumer=back-end)만 다룹니다. 즉 상한은 볼륨 드라이버가 스토리지 시스템에 적용합니다. front-end QoS spec은 바뀌지 않고 계속 하이퍼바이저가 적용하므로, 실제로 적용되는 상한은 둘 중 낮은 쪽입니다.

Volume type settings:

한국어 볼륨 타입 설정:

  • per_volume_qos_support='<is> True' marks a volume type that allows per-volume limits, the same pattern as multiattach. The CapabilitiesFilter then places volumes of this type, also on retype and migration, only on backends reporting the new capability per_volume_qos_support=True.

    한국어 per_volume_qos_support='<is> True'는 볼륨별 상한을 허용하는 볼륨 타입을 표시하며, multiattach와 같은 방식입니다. 그러면 CapabilitiesFilter가 이 타입의 볼륨을, retype과 마이그레이션 때도 포함해, 새 capability per_volume_qos_support=True를 보고하는 백엔드에만 배치합니다.

  • For each limit, the type sets the allowed range and an optional default: per_volume_qos:max_iops_min, per_volume_qos:max_iops_max, per_volume_qos:max_iops_default, and the same three keys for max_bps. _max is required for a limit that has any of these keys, _min defaults to 1, and _default must be between them. The API checks this when the extra specs of a type with per_volume_qos_support are set. On other types these scoped keys are ignored, as other scoped extra specs are.

    한국어 타입은 상한마다 허용 범위와 선택 항목인 기본값을 정합니다: per_volume_qos:max_iops_min, per_volume_qos:max_iops_max, per_volume_qos:max_iops_default, 그리고 max_bps용 같은 키 세 개입니다. 이 키 중 하나라도 있는 상한은 _max가 필수이고, _min은 기본값이 1이며, _default는 그 사이여야 합니다. API는 per_volume_qos_support가 있는 타입의 extra spec을 설정할 때 이를 검사합니다. 다른 타입에서는 다른 scope 키와 마찬가지로 이 키들을 무시합니다.

Effective limits:

한국어 적용되는 상한:

  • For each limit, Cinder computes the value to apply: the per-volume value, else the type default, else the range maximum. If the type has no range for that limit, Cinder passes no value and the driver keeps applying the QoS spec as today.

    한국어 Cinder는 상한마다 적용할 값을 계산합니다: 볼륨별 값, 없으면 타입 기본값, 그것도 없으면 범위의 최대값입니다. 타입에 그 상한의 범위가 없으면 Cinder는 값을 넘기지 않고, 드라이버는 지금처럼 QoS spec을 계속 적용합니다.

  • Type defaults are not copied into the volume. A changed default applies the next time the limits of the volume are applied.

    한국어 타입 기본값은 볼륨에 복사하지 않습니다. 기본값을 바꾸면 그 볼륨의 상한이 다음에 적용될 때 반영됩니다.

  • The driver maps the computed values to its own keys (for example maxIOPS or total_iops_sec), in place of the equivalent keys of the QoS spec. Other QoS spec keys, such as separate read and write limits, still apply.

    한국어 드라이버는 계산된 값을 자기 키(예: maxIOPS 또는 total_iops_sec)에 대응시켜, QoS spec의 같은 의미 키 대신 적용합니다. read와 write 분리 상한 같은 QoS spec의 다른 키는 계속 적용됩니다.

API checks:

한국어 API 검사:

  • A new microversion adds an optional qos object to volume create and to os-retype, and a volume action os-set_qos for available or in-use volumes.

    한국어 새 microversion이 볼륨 생성과 os-retype에 선택 항목인 qos 객체를 추가하고, available 또는 in-use 상태 볼륨에 쓰는 볼륨 action os-set_qos를 추가합니다.

  • The API rejects qos with 400 when the volume type does not have per_volume_qos_support, and when a value is outside the range of the type. A limit without a range cannot be set by a project member. Callers allowed by the volume:set_qos:any_value policy skip the range check, but not the support check.

    한국어 볼륨 타입에 per_volume_qos_support가 없거나 값이 타입의 범위를 벗어나면, API는 qos를 400으로 거부합니다. 범위가 없는 상한은 프로젝트 멤버가 설정할 수 없습니다. volume:set_qos:any_value 정책이 허용하는 호출자는 범위 검사를 건너뛰지만, 지원 여부 검사는 건너뛰지 않습니다.

  • If an administrator narrows the range of a type, values already set on volumes are kept. The new range is checked on the next os-set_qos.

    한국어 관리자가 타입의 범위를 좁혀도 볼륨에 이미 설정된 값은 유지됩니다. 새 범위는 다음 os-set_qos 때 검사합니다.

Volume operations:

한국어 볼륨 작업:

  • Create: for a type with per_volume_qos_support, the volume manager calls update_volume_qos after the driver created the volume, so drivers do not need to change create_volume and its variants. If this fails, the volume is set to error and a user message is created, the same as when a driver fails to apply the volume type QoS spec during create_volume. The request is not rescheduled, since the volume already exists on the backend. The backend volume is removed when the user deletes the volume in error.

    한국어 생성: per_volume_qos_support가 있는 타입이면, 드라이버가 볼륨을 만든 뒤 볼륨 매니저가 update_volume_qos를 호출합니다. 따라서 드라이버는 create_volume과 그 변형 메서드를 고칠 필요가 없습니다. 이 호출이 실패하면 볼륨을 error로 두고 사용자 메시지를 생성합니다. create_volume 중 드라이버가 볼륨 타입 QoS spec 적용에 실패했을 때와 같습니다. 볼륨이 이미 백엔드에 있으므로 재스케줄하지 않습니다. 백엔드 볼륨은 사용자가 error 볼륨을 삭제할 때 정리됩니다.

  • os-set_qos: the driver is called first and the database is updated only on success. On failure a user message is created and the stored values stay unchanged. null clears a per-volume value, so the type default applies again.

    한국어 os-set_qos: 드라이버를 먼저 호출하고, 성공했을 때만 데이터베이스를 갱신합니다. 실패하면 사용자 메시지가 생성되고 저장된 값은 바뀌지 않습니다. null은 볼륨별 값을 지워 타입 기본값이 다시 적용되게 합니다.

  • Retype: per-volume values are cleared, because they were checked against the old type. The values in qos of the retype request are used instead, checked against the range of the new type. Without them, the defaults of the new type apply. If the new type does not have per_volume_qos_support, no per-volume limits are applied and the QoS spec of the new type applies as today.

    한국어 retype: 볼륨별 값은 이전 타입 기준으로 검사된 값이므로 지웁니다. 대신 retype 요청의 qos 값을 새 타입의 범위로 검사해 사용합니다. qos가 없으면 새 타입의 기본값이 적용됩니다. 새 타입에 per_volume_qos_support가 없으면 볼륨별 상한은 적용하지 않고, 새 타입의 QoS spec이 지금처럼 적용됩니다.

  • Migration keeps the per-volume values, and the destination backend applies them.

    한국어 마이그레이션은 볼륨별 값을 유지하고, 대상 백엔드가 그 값을 적용합니다.

  • Volumes created from a snapshot, volume or backup do not inherit the limits.

    한국어 스냅샷, 볼륨, 백업에서 생성한 볼륨은 상한을 물려받지 않습니다.

Driver contract:

한국어 드라이버 계약:

  • New optional driver method update_volume_qos(context, volume, qos), called with the computed values. The base driver raises NotImplementedError. A driver that implements it reports per_volume_qos_support=True.

    한국어 선택 구현 드라이버 메서드 update_volume_qos(context, volume, qos)를 새로 추가하며, 계산된 값으로 호출됩니다. base 드라이버는 NotImplementedError를 발생시킵니다. 이를 구현한 드라이버는 per_volume_qos_support=True를 보고합니다.

  • A driver must use the computed values wherever it applies QoS, for example on attach or retype, not only in update_volume_qos. Otherwise the volume type QoS spec would replace them. A common helper returns the computed values for a volume.

    한국어 드라이버는 update_volume_qos뿐 아니라 attach나 retype처럼 QoS를 적용하는 모든 곳에서 계산된 값을 써야 합니다. 그렇지 않으면 볼륨 타입 QoS spec이 그 값을 덮어씁니다. 볼륨의 계산된 값은 공통 헬퍼가 돌려줍니다.

  • For a replicated volume, the driver also applies the limits to the secondary, so they stay after failover.

    한국어 복제(replication) 볼륨이면 드라이버는 secondary에도 상한을 적용해, failover 뒤에도 상한이 유지되게 합니다.

NetApp ONTAP and Dell PowerFlex are proposed as the first implementations. Support for Dell PowerStore is in development.

한국어 첫 구현으로 NetApp ONTAP과 Dell PowerFlex를 제안합니다. Dell PowerStore 지원은 개발 중입니다.

Alternatives¶

한국어 대안

  • One volume type per combination of limits, each with its own QoS spec: the number of types grows with every combination, and changing the limits of a volume needs a retype.

    한국어 상한 조합마다 볼륨 타입을 따로 만들고 타입마다 QoS spec을 붙이는 방식: 조합이 늘 때마다 볼륨 타입 수도 늘어나고, 볼륨의 상한을 바꾸려면 retype이 필요합니다.

  • QoS values in volume metadata: the owner can set any value without bounds or validation, and the keys are an undocumented contract between the API and the drivers.

    한국어 볼륨 메타데이터에 QoS 값을 넣는 방식: 소유자가 범위 제한이나 검증 없이 아무 값이나 넣을 수 있고, 이 키들은 API와 드라이버 사이에 문서화되지 않은 약속이 됩니다.

  • Range in the QoS spec instead of the volume type extra specs: project members cannot read QoS specs, and opening them would show every key of every QoS spec. Back-end QoS spec keys go to the drivers, and some drivers reject unknown keys (for example NetApp). A type without a QoS spec would need an empty one only to hold the range.

    한국어 범위를 볼륨 타입 extra spec 대신 QoS spec에 두는 방식: 프로젝트 멤버는 QoS spec을 읽을 수 없고, 열어 주면 모든 QoS spec의 모든 키가 보입니다. back-end QoS spec 키는 드라이버로 전달되는데, 모르는 키를 거부하는 드라이버가 있습니다(예: NetApp). QoS spec이 없는 타입은 범위만 담으려고 빈 QoS spec을 붙여야 합니다.

Data model impact¶

한국어 데이터 모델 영향

Two nullable columns on volumes: qos_max_iops (Integer) and qos_max_bps (BigInteger, since Integer stops at about 2.1 GB/s). NULL means no per-volume value, so the rules above apply and existing rows need no data migration. The Volume object gets a new version, and obj_make_compatible drops the fields for older targets.

한국어 volumes 테이블에 nullable 컬럼 두 개를 추가합니다: qos_max_iops(Integer)와 qos_max_bps(BigInteger, Integer는 약 2.1 GB/s가 한계이므로). NULL은 볼륨별 값이 없다는 뜻이므로 위 규칙이 적용되고, 기존 행에 데이터 마이그레이션이 필요 없습니다. Volume 객체는 새 버전이 되고, obj_make_compatible이 이전 버전 대상에 대해서는 이 필드들을 제거합니다.

REST API impact¶

한국어 REST API 영향

All changes are introduced in one new microversion.

한국어 모든 변경을 하나의 새 microversion으로 도입합니다.

Create a volume with limits:

한국어 상한을 지정해 볼륨 생성:

  • POST /v3/{project_id}/volumes, response 202, errors 400 (invalid values, values outside the range, or a type without per_volume_qos_support) and 403.

    한국어 POST /v3/{project_id}/volumes, 응답 202, 오류 400(잘못된 값, 범위를 벗어난 값, 또는 per_volume_qos_support가 없는 타입)과 403.

  • New optional attribute (integers >= 1, qos must not be empty):

    한국어 새 선택 속성(1 이상의 정수, qos는 비어 있으면 안 됨):

    {"volume": {"size": 10, "qos": {"max_iops": 3000, "max_bps": 125000000}}}

Set or clear limits on an existing volume:

한국어 기존 볼륨의 상한 설정 또는 해제:

  • POST /v3/{project_id}/volumes/{volume_id}/action

    한국어 POST /v3/{project_id}/volumes/{volume_id}/action

  • Body: {"os-set_qos": {"max_iops": 5000, "max_bps": null}}. null clears that limit (back to the type default). At least one key is required and additionalProperties is False.

    한국어 본문: {"os-set_qos": {"max_iops": 5000, "max_bps": null}}. null은 해당 상한을 해제합니다(타입 기본값으로 복귀). 키는 최소 하나 필요하며 additionalProperties는 False입니다.

  • Response 202. Errors: 400 (invalid values, values outside the range of the volume type, a type without per_volume_qos_support, or volume not available or in-use), 403 (policy), 404 (volume not found).

    한국어 응답 202. 오류: 400(잘못된 값, 볼륨 타입 범위를 벗어난 값, per_volume_qos_support가 없는 타입, 또는 볼륨이 available이나 in-use 상태가 아님), 403(정책), 404(볼륨 없음).

  • Asynchronous (RPC cast). The new values show in the volume detail after the backend accepted them. A backend failure is reported via user messages.

    한국어 비동기 방식(RPC cast)입니다. 새 값은 백엔드가 받아들인 뒤에 볼륨 상세 정보에 나타납니다. 백엔드 실패는 사용자 메시지로 보고됩니다.

Retype with limits:

한국어 상한을 지정해 retype:

  • POST /v3/{project_id}/volumes/{volume_id}/action

    한국어 POST /v3/{project_id}/volumes/{volume_id}/action

  • Body: {"os-retype": {"new_type": "gold", "qos": {"max_iops": 8000}}}. qos is optional and follows the same rules as on create, against the new type.

    한국어 본문: {"os-retype": {"new_type": "gold", "qos": {"max_iops": 8000}}}. qos는 선택 항목이며, 생성 때와 같은 규칙을 새 타입 기준으로 따릅니다.

Volume detail returns qos with max_iops and max_bps (null when not set) from the new microversion.

한국어 새 microversion부터 볼륨 상세 정보는 max_iops와 max_bps를 담은 qos를 반환합니다(설정되지 않았으면 null).

per_volume_qos_support and the six per_volume_qos:* keys are added to the user visible extra specs, so project members can see which types allow per-volume limits and their ranges.

한국어 per_volume_qos_support와 per_volume_qos:* 키 6개를 사용자에게 보이는 extra spec 목록에 추가해, 프로젝트 멤버가 볼륨별 상한을 허용하는 타입과 그 범위를 볼 수 있게 합니다.

Policy: two new rules, also checked when qos is present on create or retype.

한국어 정책: 새 규칙 두 개를 추가하며, 생성이나 retype 요청에 qos가 있을 때도 검사합니다.

  • volume:set_qos, default rule:xena_system_admin_or_project_member (same as volume:create): set limits within the range of the volume type.

    한국어 volume:set_qos, 기본값 rule:xena_system_admin_or_project_member(volume:create와 같음): 볼륨 타입 범위 안에서 상한을 설정합니다.

  • volume:set_qos:any_value, default rule:admin_api: set limits outside that range, or limits for which the volume type defines no range.

    한국어 volume:set_qos:any_value, 기본값 rule:admin_api: 범위를 벗어난 상한이나, 볼륨 타입에 범위가 정의되지 않은 상한을 설정합니다.

Security impact¶

한국어 보안 영향

Project members can change the limits of their own volumes, but only within the range set by the administrator in the volume type. A volume type without a range keeps per-volume limits admin-only.

한국어 프로젝트 멤버는 자기 볼륨의 상한을 바꿀 수 있지만, 관리자가 볼륨 타입에 정한 범위 안에서만 가능합니다. 범위가 없는 볼륨 타입에서는 볼륨별 상한이 계속 관리자 전용입니다.

Active/Active HA impact¶

한국어 Active/Active HA 영향

None

한국어 없음

Notifications impact¶

한국어 알림 영향

os-set_qos sends volume.set_qos.start and volume.set_qos.end notifications with the new values, so billing systems can track them.

한국어 os-set_qos는 새 값을 담은 volume.set_qos.start와 volume.set_qos.end 알림을 보내, 과금 시스템이 변경을 추적할 수 있게 합니다.

Other end user impact¶

한국어 기타 최종 사용자 영향

New qos attribute in volume detail. python-cinderclient and openstacksdk need the new create argument and action.

한국어 볼륨 상세 정보에 새 qos 속성이 생깁니다. python-cinderclient와 openstacksdk에 새 생성 인자와 action 지원이 필요합니다.

Performance Impact¶

한국어 성능 영향

One extra backend call after creation and retype, only for volume types with per_volume_qos_support.

한국어 per_volume_qos_support가 있는 볼륨 타입에 한해, 생성과 retype 뒤 백엔드 호출이 한 번 늘어납니다.

Other deployer impact¶

한국어 기타 배포자 영향

New database migration. The API refuses to send the new RPC to an older volume service during a rolling upgrade. To allow per-volume limits, deployers add per_volume_qos_support='<is> True' and the per_volume_qos:* range extra specs to volume types.

한국어 새 데이터베이스 마이그레이션이 추가됩니다. 롤링 업그레이드 중에는 API가 이전 버전 볼륨 서비스로 새 RPC를 보내지 않습니다. 볼륨별 상한을 허용하려면 배포자가 볼륨 타입에 per_volume_qos_support='<is> True'와 per_volume_qos:* 범위 extra spec을 추가합니다.

Developer impact¶

한국어 개발자 영향

Driver maintainers may implement update_volume_qos and then report per_volume_qos_support=True in the volume stats. They must use the computed values in every path that applies QoS, and on the replication secondary. The support matrix gets a new row.

한국어 드라이버 메인테이너는 update_volume_qos를 구현할 수 있으며, 구현하면 볼륨 통계에 per_volume_qos_support=True를 보고합니다. QoS를 적용하는 모든 경로와 복제 secondary에서 계산된 값을 써야 합니다. support matrix에 새 행이 추가됩니다.

Testing¶

한국어 테스트

Tempest API tests for create with qos, os-set_qos and retype, including values outside the range of the volume type, skipped when the backend does not support per-volume QoS. The LVM driver used in the gate does not implement it. The RBD driver already applies back-end QoS, so we will try to add support there too if possible, which would let the upstream Ceph job cover it.

한국어 qos를 포함한 생성, os-set_qos, retype에 대한 Tempest API 테스트를 추가하며(볼륨 타입 범위를 벗어난 값 포함), 백엔드가 볼륨별 QoS를 지원하지 않으면 건너뜁니다. 게이트에서 쓰는 LVM 드라이버는 이를 구현하지 않습니다. RBD 드라이버는 이미 back-end QoS를 적용하므로, 가능하면 RBD에도 지원을 추가해 upstream Ceph 잡에서 검증할 수 있게 해 보겠습니다.
